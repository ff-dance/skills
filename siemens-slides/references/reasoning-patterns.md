# Siemens Reasoning Patterns

内容页先选论证模式，再选 layout。论证模式回答“这页在证明什么”，layout 回答“这个结论最适合长成什么样”。

补充原则：
- 这些模式名是 agent 的内部路由语言，不应原样出现在最终页面文案中。
- 当页面需要总览式压缩时，优先使用“结构化总览”思路，而不是把 `MECE` 作为显性标题或标签。

## 模式选择决策树

按用户要回答的决策问题先路由：

- 如果在回答“我们现在在哪 / 出什么问题了”：
  - 优先看 `① Sit-Com-Sol`、`② 根因分析`、`③ 成熟度评估`、`④ 问题优先级矩阵`
- 如果在回答“为什么 / 选哪个 / 数据说明了什么”：
  - 优先看 `⑤ 结构化总览`、`⑥ 对比分析`、`⑦ 假设-验证-结论`、`⑧ 数据驱动洞察`、`⑨ AI驱动根因发现`
- 如果在回答“我们要去哪 / 体系怎么设计 / 价值在哪里”：
  - 优先看 `⑩ 愿景 vs 现状 + 差距`、`⑪ 技术架构蓝图`、`⑫ AI应用场景矩阵`、`⑬ ROI`
- 如果在回答“谁在什么时候做什么 / 如何落地”：
  - 优先看 `⑭ 战略路线图`、`⑮ 实施计划`、`⑯ 组织与治理`
- 如果在回答“流程怎么跑 / 数据怎么流 / 生态如何连接 / 风险如何表达”：
  - 优先看 `⑰ 端到端数据流`、`⑱ 业务流程泳道图`、`⑲ 能力建设路径`、`⑳ 供应商/生态图谱`、`㉑ 标杆对比`、`㉒ 风险全景图`、`㉓ 速赢清单`

## 高频核心模式

优先使用以下高频模式：
- `① Sit-Com-Sol`
- `⑤ 结构化总览`
- `⑥ 对比分析`
- `⑧ 数据驱动洞察`
- `⑩ 愿景 vs 现状 + 差距`
- `⑭ 战略路线图`
- `⑰ 端到端数据流`
- `⑱ 业务流程泳道图`
- `⑲ 能力建设路径`
- `㉓ 速赢清单`

## 模式规格表

| 模式 | 必要输入 | L2 hero | L3 结构 | failure_signals | compression_suitability | degrade_strategy_hint |
|---|---|---|---|---|---|---|
| `① Sit-Com-Sol` | 痛点、根因、举措 | 至少一个量化痛点 | 三段递进 | 三栏只是并列事实；标题只是“问题分析” | 中 | 三栏缩成三段重点 + 1 个主证据 |
| `② 根因分析` | 现象、因果链、干预点 | 一个关键症状或损失事实 | 5-7 个因果节点 | 做成复杂鱼骨图；只是罗列原因 | 低 | 降级为 3 段因果链 |
| `③ 成熟度评估` | 维度评分、当前阶段、目标阶段 | 最大差距或总体评分 | 5-6 个维度 | 维度太多；没有清晰差距 | 中 | 降级为状态总览 + 3 个关键维度 |
| `④ 问题优先级矩阵` | 影响、难度、排序标准 | 第一优先级问题 | 矩阵或层级排序 | 没有清晰排序标准 | 低 | 降级为优先级列表 |
| `⑤ 结构化总览` | 3-5 个关键维度与判断 | 一个总括判断 | 并列维度、统一层级 | 维度交叉；没有总括判断；页面只剩四块同构文字框 | 高 | 降级为 3 栏并列块或 1 个 hero summary + 2-3 个支撑维度 |
| `⑥ 对比分析` | 方案、标准、推荐结论 | 推荐方案或关键对比结果 | 对称比较 + 推荐理由 | 只列差异不做推荐 | 高 | 降级为表格 + 推荐栏 |
| `⑦ 假设-验证-结论` | 一个核心假设、验证证据、结论 | 最关键的验证结果 | 假设 → 验证 → 结论 | 一页同时验证多个假设 | 中 | 降级为主结论 + 2 个证据点 |
| `⑧ 数据驱动洞察` | 核心数据关系、结论、少量解释 | hero number 或主图式证据块 | 少量解释文字支撑洞察 | 数据很多但没有清晰结论；没有 hero evidence | 高 | 降级为 hero number + supporting points |
| `⑨ AI驱动根因发现` | 传统判断、AI 发现、差异价值 | AI 与传统判断的差异 | 旧判断 vs 新发现 | 没有明显 AI 特有发现 | 中 | 降级为对照双栏 |
| `⑩ 愿景 vs 现状 + 差距` | 现状、目标、差距、行动方向 | 最大差距或提升幅度 | 两端对照 + 中间桥接 | 现状与愿景只是口号 | 高 | 降级为现状/目标双栏 |
| `⑪ 技术架构蓝图` | 分层架构、模块、边界 | 核心平台层或关键骨架 | 分层结构 | 做成工程图或接口清单 | 中 | 降级为 3 层框架图 |
| `⑫ AI应用场景矩阵` | 场景、价值、难度 | 最高价值场景 | 场景矩阵或分组 | 场景太多，页面失焦 | 中 | 降级为 Top 3 场景 |
| `⑬ ROI` | 投入、收益、回收期 | 回收期 / 净收益 / ROI 大数字 | 收益来源 + 推荐判断 | 只有定性结论，没有量化结果 | 高 | 降级为 hero ROI + 3 点收益 |
| `⑭ 战略路线图` | 阶段名、里程碑、关键动作 | 关键里程碑或阶段主线 | 顺序阶段 | 变成细粒度项目计划 | 高 | 降级为 3 阶段路线 |
| `⑮ 实施计划` | 阶段、责任、时间、交付 | 关键阶段或责任安排 | 轻量计划 | 变成密集时间表 | 中 | 降级为阶段清单 |
| `⑯ 组织与治理` | 角色、分工、治理关系 | 关键治理骨架 | 层级或 RACI 关系 | 角色过多，像组织树 | 中 | 降级为 3 层治理框架 |
| `⑰ 端到端数据流` | 节点、流向、数据对象 | 主流程链 | 起点、终点、流向清晰 | 箭头没方向；系统名过载 | 高 | 降级为轻量 process flow |
| `⑱ 业务流程泳道图` | 步骤、角色、交接点、前后关系 | 主流程链或关键改进步骤 | 阶段或泳道分段 | 节点太多；角色和步骤混在一起 | 中 | 降级为轻量 process flow |
| `⑲ 能力建设路径` | 当前状态、目标状态、阶段能力项 | 目标能力或关键跳跃 | 阶段提升路径 | 没有阶段性，只列能力清单 | 高 | 降级为 3 阶段台阶图 |
| `⑳ 供应商/生态图谱` | 角色、关系、边界 | 核心生态关系 | 轻量网络或左右映射 | 关系网过密，读不出主次 | 低 | 降级为左右生态映射 |
| `㉑ 标杆对比` | 对标对象、差距、结论 | 最大差距或最佳实践对照 | 标准化对比 + 差距总结 | 只是列事实，没有判断 | 高 | 降级为表格 + 结论条 |
| `㉒ 风险全景图` | 风险点、影响、概率、优先级 | 最高风险项 | 少量关键风险 | 风险点泛滥，页面失焦 | 中 | 降级为 Top 3 风险 |
| `㉓ 速赢清单` | 行动项、收益、难度、优先级 | 最高优先速赢项 | 行动清单 + 收益说明 + 排序 | 长期战略混入；没有排序 | 高 | 降级为 Top 3 速赢项 |
