# 咨询式 Storytelling 框架

在输出完整 PPT Storytelling、逐页大纲、Workshop 议程、高管决策叙事、项目交付汇报或 Storytelling 质量检查时使用本参考。

## 故事线框架选择

| 场景 | 推荐故事线 |
|---|---|
| 高管汇报 | Pyramid Principle + Why-What-How-Value |
| 售前方案 | SCQA + 客户痛点到价值 |
| 项目交付 | 诊断、蓝图、路线图、价值 |
| Workshop | 现状共识、问题探索、场景优先级、下一步行动 |
| 技术方案 | 业务需求、能力设计、架构方案、实施路径 |

## 不同场景的推荐逻辑

### 售前客户方案

1. 客户所处行业正在发生变化。
2. 当前运营模式面临新的挑战。
3. 挑战背后的根因是流程、数据、系统和组织协同不足。
4. 因此需要建立面向未来的数字化运营体系。
5. Siemens 或相关解决方案可提供端到端能力支持。
6. 建议从高价值场景切入，分阶段推进。
7. 下一步建议开展联合诊断或方案共创。

### 高管决策

1. 外部趋势和内部挑战正在提高变革紧迫性。
2. 当前能力与未来业务要求之间存在差距。
3. 如果不系统推进，将影响效率、增长、风险控制或竞争力。
4. 建议聚焦若干高价值举措，形成可落地的转型组合。
5. 管理层需要决策方向、投资优先级、治理机制和下一步行动。

### 项目交付

1. 项目的目标是明确现状、差距和未来方向。
2. 通过访谈、调研、流程分析和系统梳理识别关键问题。
3. 现状差距集中在流程、数据、系统、组织和治理方面。
4. 这些差距影响效率、质量、成本、交付或风险控制。
5. 未来目标蓝图需要围绕端到端价值流设计。
6. 建议通过分阶段路线图逐步实现能力提升。
7. 下一步进入试点设计、实施准备或推广阶段。

### Workshop 引导

1. 对齐本次 Workshop 的目标和背景。
2. 建立对当前挑战的共同认知。
3. 识别关键业务场景和痛点。
4. 对场景进行价值与可行性优先级排序。
5. 共创目标蓝图和初步解决方向。
6. 明确下一步行动、责任人和交付物。

## 输出模式

### 快速故事线模式

在用户要求快速初版时使用。

输出：

- 一句话故事线
- SCQA
- 章节结构
- 逐页标题
- Key Message

### 详细 PPT 故事线模式

在正式客户材料场景中使用。

输出：

- 汇报目标理解
- 故事线
- SCQA
- 章节结构
- 逐页大纲
- 详细讲述逻辑
- 图表建议
- 表达建议
- 自检清单

### 高管汇报模式

用于 CXO、Steering Committee 或投资审批场景。

规则：

- 结论先行。
- 在前三页呈现价值、决策事项、投资优先级和风险。
- 降低技术细节比例。
- 说明不采取行动的成本或风险。
- 明确管理层需要做出的决策。

### 售前方案模式

用于推动客户机会进展。

规则：

- 从客户痛点切入。
- 体现 Siemens 能力，但避免产品化堆砌。
- 聚焦价值场景。
- 推动下一步进入 Workshop、诊断、方案共创或试点定义。

### 项目交付汇报模式

用于咨询交付输出。

规则：

- 解释诊断方法和证据。
- 清晰展示差距。
- 呈现目标蓝图。
- 给出路线图和实施建议。

### Workshop 引导模式

用于客户共创。

规则：

- 对齐 Workshop 目标。
- 包含互动环节。
- 引导痛点发现。
- 支持场景价值与可行性排序。
- 以下一步行动、责任人和交付物收束。

## 咨询表达规则

### 页标题必须是观点句

不推荐：

> 行业趋势

推荐：

> 制造企业正面临更高的效率、质量和柔性交付要求

### 每页必须只有一个 Key Message

推荐格式：

> Key Message：数据贯通是数字化工厂落地的关键基础。

### 先讲问题，再讲方案

薄弱结构：

1. Siemens 介绍
2. 产品组合
3. 功能模块
4. 客户案例
5. 报价

推荐结构：

1. 客户业务挑战
2. 当前问题根因
3. 目标运营蓝图
4. 解决方案框架
5. 实施路线图
6. 价值收益
7. 下一步行动

### 避免过度承诺

不推荐：

> 该方案一定可以帮助客户降低 30% 成本。

推荐：

> 成本改善潜力可在诊断阶段结合当前基线数据进一步评估，并在试点阶段验证。

### Siemens 能力必须服务于客户问题

不推荐：

> Siemens 产品非常全面，功能非常强大。

推荐：

> Siemens 可结合自动化、工业软件、数字化咨询和生态实施能力，支持客户从现状诊断、目标蓝图到试点落地，降低数字化转型复杂度。

## 可视化建议

| 内容类型 | 推荐图表 | 使用目的 |
|---|---|---|
| 行业趋势 | 趋势驱动图 | 建立转型必要性 |
| 客户痛点 | 痛点矩阵 | 汇总问题全貌 |
| 根因分析 | 问题树或鱼骨图 | 从现象进入本质 |
| 目标状态 | 数字化工厂蓝图 | 描绘未来能力 |
| 解决方案 | 场景地图或能力地图 | 展示方案组成 |
| 技术支撑 | IT/OT 架构图 | 说明系统打通路径 |
| 实施计划 | 三阶段路线图 | 降低落地不确定性 |
| 业务价值 | 价值树 | 建立价值衡量体系 |
| 治理机制 | RACI 或治理模型 | 说明组织保障 |

## 示例参考

### 输入

我需要给一家汽车零部件制造企业做数字化工厂方案汇报。听众是 COO、工厂厂长和 IT 负责人。目标是推动后续联合 Workshop。客户痛点包括生产过程不透明、质量追溯困难、设备停机较多、系统之间数据不打通。希望 15 页左右，偏咨询方案，不要太产品化，需要体现 Siemens 的端到端能力。

### 简化输出形态

- 推荐故事线方法：SCQA + Why-What-How-Value
- 一句话故事线：客户当前面临的生产不透明、质量追溯困难、设备停机和数据孤岛问题，本质上是端到端运营闭环不足；建议通过数字化工厂目标蓝图和分阶段建设路径，逐步构建可视、可控、可优化的生产运营体系。
- 章节结构：
  1. 背景与挑战
  2. 当前痛点与根因
  3. 目标蓝图
  4. 解决方案框架
  5. 实施路径与价值
  6. 下一步行动
- 代表性页标题：当前运营痛点集中在生产、质量、设备和数据四个方面
- 代表性 Key Message：多个表面问题背后反映的是管理闭环不足。

## 测试提示词

用以下提示词验证技能是否有效：

1. 请帮我生成一个数字化工厂售前方案的 storytelling。客户是电子制造企业，听众是 COO 和 IT 负责人，痛点是生产计划频繁变更、现场数据不透明、质量问题定位慢、设备利用率不高。目标是推动后续 Workshop，页数 12-15 页，需要体现 Siemens 能力，但不要太产品化。
2. 请帮我生成一个高管汇报版 storytelling。主题是制造企业数字化转型路线图，听众是 CEO、CFO 和 COO，目标是争取立项。希望控制在 8 页以内，重点讲业务价值、投资优先级和风险控制。
3. 请帮我为一个智能制造诊断项目最终汇报设计 storytelling。我们已经完成访谈、现场调研和系统梳理，发现主要问题是流程断点、数据标准不统一、系统烟囱化和组织职责不清。希望输出 20 页左右的 PPT 大纲。
4. 请帮我设计一个客户数字化工厂共创 Workshop 的 storytelling 和 PPT 大纲。目标是帮助客户识别高价值场景并确定试点方向。参与人包括工厂厂长、生产经理、质量经理、设备经理和 IT 负责人。
